The backend seam keeps only what the run layer reads ([#860](https://github.com/LupoLab/solprop/issues/860), [#861](https://github.com/LupoLab/solprop/issues/861), [#862](https://github.com/LupoLab/solprop/issues/862)). `Backend.reads_transverse_edge` and `march_export_refusal` (on `Backend` and `RunSession`) are gone, every backend having given one answer, and so are `ExecutionOptions.backend_options`, `solprop.backends.session.SessionBackend`, `solprop.backends.numpy_ref.construct` (construct `NumpyRefBackend` directly), the reference's `helpers` and `propagator_default` attributes, and `refuse_formulation`, `COUPLED_SECTIONS` and `EXPONENTIAL_REPRESENTATIONS` of `solprop.backends.exponential`, whose one Adams refusal is now `refuse_adams`. `RunSession` declares `march_refusal`, `in_flight` and `failure_ticket`. The reference's session and marches moved from `solprop.backends.host` into `solprop.backends.numpy_ref` (`session`, `session_parts` and the `marches` package, class names unchanged); `check_preparation`, `foreign_request` and `AttemptListener` are now in `solprop.backends.session`, and `solprop.backends.session_core` is gone. `MAX_N_POL` is `solprop.nonlinear.responses.MAX_N_POL` alone. A hand-built problem whose polarisation count, vector Raman terms or TDSE statistics a backend used to refuse with `BackendError` is now refused by `validate_run` with `TranslationError`, as is a `flags.has_raman` that no Raman term backs.
