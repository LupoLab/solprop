Runs on a CUDA build of the native backend now go through the native execution session when they use Adams or an embedded Runge-Kutta tableau on a modal route, with saved planes, periodic statistics rows, step planes, the temporal boundary monitor and resumed Adams history, with the same steps, statistics and fields as before ([SEP 47](docs/dev/seps/sep-0047-run-ownership.md)). A saved plane's field crosses from the device once, into its destination, with no extra host copy. On a GPU build, spatial routes, the low-storage replay, dense output, a transverse edge, noise models and `Batch` groups still use the backend's own march. HIP builds keep the backend's own march until the native session is qualified on an AMD GPU.
