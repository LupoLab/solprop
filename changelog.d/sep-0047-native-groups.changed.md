A `Batch` scan's group of native points now runs in the native group session on the CPU build, and is admitted to it on a GPU build (CUDA or HIP; run on an NVIDIA A40, HIP and data-centre NVIDIA evidence to follow): each member in its own native execution session, which steps it natively from one save plane to the next and keeps its own events, statistics rows, boundary monitor and exports, with the same fields, statistics and step records as before. An Adams group no longer warns `HostMarchWarning` for its replay. A member's monitor that refuses its launch now ends it after its launch plane is committed, as a run of the point alone does, and in a group-wide failure the members that had already taken their turn report the steps they committed, eligible for a checkpoint. A group the native group session does not run (a feature the native session refuses, an adaptive member, step or interpolated planes) runs on the lockstep batch as before ([SEP 47](docs/dev/seps/sep-0047-run-ownership.md)).
