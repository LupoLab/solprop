The native backend reads a machine calibration ([SEP 46](docs/dev/seps/sep-0046-machine-calibration.md)) from a per-user store in the platform's cache directory (`SOLPROP_CACHE_DIR` moves it; `SOLPROP_CALIBRATION_PATH` adds read-only directories, such as a cluster's profiles for each node type). Each run records in its metadata (`calibration`) the profile it found and the CPU execution settings its workspace applied, read back from the workspace beside the built-in value of each. `solprop calibrate --show`, `--export`, `--import` and `--clear` show and manage profiles. The operation thresholds, medium and compact widths and the stable-team rule moved from the native source into a built-in table keyed by operating system; without a profile, or with `SOLPROP_CALIBRATION=off`, every run uses exactly the former values, and `BuildInfo`'s threshold fields now report that table for the process, divided on Apple silicon's spinning top tier as the runs use it.
