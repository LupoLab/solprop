Runs on the native backend's CPU build now go through the native execution session whenever it admits the run ([SEP 47](docs/dev/seps/sep-0047-run-ownership.md)), with the same steps, fields, statistics, step records and call ledgers as before. The session also runs resumed runs, carrying the Adams history and the call ledgers, the input and modified noise models, the boundary monitor (including a free-space run's transverse edge), dense output and the low-storage replay, and it exports the Adams history beside each saved plane and checkpoint. A signal during a run is still handled once the native call returns, within 256 attempts or 0.1 s; the run's checkpoint then includes every attempt made. Some runs still use the backend's own march, as before: comparison methods and methods other than Adams and the embedded Runge-Kutta tableaux; controllers that override `PIController`'s methods; TDSE responses; the input noise beside a transverse edge; a noise model on a propagator stored as a z table; marches the backend steps on the host (low-storage stage rows the host forms, and on a device build a coupled flow off its eigenbasis route or wider than 16 channels); and the plane statistics the host finishes, such as `beam_radius` and `fwhm_r`. A `Batch` scan's group refuses noise models in the native group session and runs them on the lockstep batch. On a CPU build, a coupled flow wider than 16 channels or with bins off its eigenbasis route now runs on the native Adams march in the session rather than on solprop's Python march: a bin off the route takes its matrix functions from the scaled Taylor series and squaring of the augmented exponential rather than SciPy's `expm`, a difference at the rounding level, and a step whose exponent there would need more than 30 squarings is refused by name.
