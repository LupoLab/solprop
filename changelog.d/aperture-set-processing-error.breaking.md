A malformed `stats.ApertureSet`, and an unknown profile or weighting passed to `stats.check_aperture_choices`, now raise `ProcessingError`, the error of every other malformed `StatsSpec`, instead of `OutputError`; so does a spec that does not fit a line grid (an aperture centred off `y = 0`, a half-plane bounded in y or an ellipse, or a spectral region whose `kappa_y` interval excludes zero). Code that caught `OutputError` around building a spec's apertures, or a line run's statistics tables, catches `ProcessingError` instead.
